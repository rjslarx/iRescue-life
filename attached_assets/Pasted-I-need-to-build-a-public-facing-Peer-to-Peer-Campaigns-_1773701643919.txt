I need to build a public-facing "Peer-to-Peer Campaigns & Pledges" module. This will allow rescues to create custom fundraising landing pages for specific animals or goals (e.g., a weight-loss journey or heartworm treatment).

1. Database Schema Updates:
   - Create a `campaigns` table: `id`, `tenant_id`, `animal_id` (nullable), `title`, `description`, `goal_target` (Integer, e.g., 7 for pounds, or 5000 for dollars), `goal_type` (Enum: 'currency', 'units'), `current_progress` (default 0), `status` (active, completed).
   - Create a `campaign_updates` table: `id`, `campaign_id`, `update_text`, `image_url`, `created_at`. (This creates a social-media-style timeline on the campaign page).
   - Create a `pledges` table: `id`, `campaign_id`, `donor_name`, `donor_email`, `pledge_type` (Enum: 'per_unit', 'flat_donation'), `amount`, `stripe_session_id`, `payment_status`.

2. The Public Landing Page UI (`/campaigns/:id`):
   - Build a clean, shareable public page.
   - Top Section: Campaign Title, Main Image, and a bold Progress Bar (e.g., "3 out of 7 lbs lost!").
   - Middle Section: A chronological feed pulling from `campaign_updates` (e.g., video clips, weigh-in photos, diet complaints).
   - Right Sidebar (or sticky bottom bar on mobile): The "Back this Campaign" card.

3. The Donation/Pledge Logic:
   - Create a form with two tabs: "Pledge Per Pound/Unit" and "One-Time Flat Donation".
   - If they select "Pledge Per Pound" (e.g., $10/lb), save the pledge to the database with `payment_status = pending`. (You will invoice them at the end of the campaign).
   - If they select "One-Time Donation", integrate Stripe Checkout. Route them to a Stripe payment link, and upon successful webhook return, log the payment and update the rescue's financial dashboard.

4. The Tenant Dashboard (Campaign Manager):
   - Create a view for the shelter manager to create new campaigns, post updates (which instantly push to the public page), and view a list of all donors and pending pledges.
