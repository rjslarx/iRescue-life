I need to build an "Omnichannel Communications Switchboard" for Tenant Admins. This will act as a master control panel to monitor past messages and control/cancel future scheduled messages (both SMS and Email).

1. Database Schema (`message_queue` table):
   - Create a unified table for all comms: `id`, `tenant_id`, `channel` ('sms' | 'email'), `direction` ('outbound' | 'inbound'), `recipient_user_id` (FK), `related_animal_id` (FK, nullable), `message_body`, `subject` (for emails).
   - Add scheduling & status columns: `scheduled_for` (timestamp), `sent_at` (timestamp, nullable), `status` ('scheduled', 'processing', 'delivered', 'failed', 'cancelled').
   - Add tracking columns: `provider_sid` (Twilio SID or Email Message ID), `error_log` (text).

2. The Backend Engine (The Cron Dispatcher):
   - Refactor our outbound messaging logic. Instead of sending texts/emails immediately, the system should INSERT a row into `message_queue` with a `scheduled_for` time and `status: 'scheduled'`.
   - Create a Cron Job that runs every minute: Query the `message_queue` for `status: 'scheduled'` AND `scheduled_for <= NOW()`.
   - Loop through the results, dispatch via Twilio (if SMS) or our Email provider (if Email), update `sent_at` to NOW(), and change status to `processing` (until the webhook confirms delivery).

3. The Switchboard UI (`<CommunicationsSwitchboard />`):
   - Create a Tenant Admin page: `/admin/communications`.
   - Render a data table displaying the `message_queue`. 
   - Add a robust filtering header: 
     - Channel Dropdown: (All, SMS, Email)
     - Status Dropdown: (All, Scheduled, Delivered, Failed, Cancelled)
     - Search Bar: Search by recipient name or message body.
   - Use colored status badges: 🟡 Scheduled, 🟢 Delivered, 🔴 Failed, ⚫ Cancelled.

4. The "Control" Actions (Crucial Feature):
   - For any row where `status === 'scheduled'`, render a "Cancel" action button.
   - When clicked, update that row's status to `cancelled` so the Cron Dispatcher ignores it.
   - Add a global "Pause Outbound Comms" toggle at the top of the page. If toggled ON, the Cron Dispatcher should instantly stop sending messages for this specific `tenant_id` (emergency kill switch).
