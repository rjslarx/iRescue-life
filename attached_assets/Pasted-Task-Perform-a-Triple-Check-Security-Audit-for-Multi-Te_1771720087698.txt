Task: Perform a "Triple-Check" Security Audit for Multi-Tenant Isolation.

Please audit the entire codebase to ensure strict tenant isolation. A user from Tenant A must never be able to read, edit, or delete data belonging to Tenant B. Execute the following checklist:

Phase 1: Database & Row Level Security (RLS)
1. Inspect all database schema definitions (e.g., animals, medical_records, users, fosters, preventative_care, compliance_monitor).
2. Verify that every single table (except global tables like `tenants` or `subscription_plans`) has a `tenant_id` column.
3. If using Supabase/Postgres, ensure Row Level Security (RLS) is enabled on all tenant-specific tables.
4. Verify or create RLS policies enforcing that `tenant_id` must match the authenticated user's `tenant_id` for ALL operations (SELECT, INSERT, UPDATE, DELETE).

Phase 2: Backend API & ORM Audit
1. Audit all backend route handlers and API endpoints.
2. Confirm that the client CANNOT arbitrarily pass a `tenant_id` in the request body to access other data. The `tenant_id` MUST be extracted securely from the server-side session/auth token (e.g., `req.user.tenant_id`).
3. Verify that every database query (using Prisma, Drizzle, or raw SQL) explicitly includes a `WHERE tenant_id = ?` clause.
4. Flag any endpoints that fetch data by `id` (e.g., `GET /api/animals/:id`) but fail to verify that the fetched record's `tenant_id` matches the session's `tenant_id`.

Phase 3: Frontend Security & State Leakage
1. Audit the frontend data fetching hooks (e.g., React Query, SWR, or Redux).
2. Ensure that when a user logs out, the local cache and global state are completely cleared so the next user on the same device does not see cached data.

Phase 4: Generate Security Tests
1. Create an integration test specifically for tenant isolation.
2. The test should mock two users (User A in Tenant A, User B in Tenant B).
3. The test must assert that User A receives a 403 Forbidden or 404 Not Found when attempting to fetch an Animal ID that belongs to Tenant B.

Output Requirement:
Provide a summary of any vulnerabilities found and automatically apply the fixes to lock down the queries and database policies.
